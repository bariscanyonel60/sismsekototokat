# Şimşek Oto – Kurumsal Web Sitesi

Next.js 16 (App Router, Turbopack) + React 19 + TypeScript + Tailwind CSS v4. Kurumsal site + yedek parça kataloğu; içerik `src/data/` altındaki veri dosyalarından, yedek parça kataloğu `content/catalog.json`'dan (admin paneliyle düzenlenir) gelir.

## Komutlar

| Amaç | Komut |
| --- | --- |
| Geliştirme sunucusu | `npm run dev` (http://localhost:3000) |
| Tip kontrolü | `npm run typecheck` |
| Lint | `npm run lint` |
| Production build | `npm run build` |
| Production sunucu | `npm run start` |
| Admin şifre özeti + oturum anahtarı üret | `npm run admin:hash -- "yeni-sifre"` |
| SEO denetimi (katalog + build çıktısı; build sonrası) | `npm run seo:audit` |

Bir değişikliği doğrulamak için minimum döngü: `npm run typecheck && npm run lint && npm run build`.

## Ortam değişkenleri

- `NEXT_PUBLIC_SITE_URL` – canonical/OG/sitemap için gerçek alan adı (örn. `https://simsekoto.com.tr`). Tanımlı değilse sırasıyla `VERCEL_PROJECT_PRODUCTION_URL`, Netlify `URL`, en son `http://localhost:3000` kullanılır (`src/data/site.ts`).
- `GOOGLE_SITE_VERIFICATION` – Google Search Console "HTML etiketi" doğrulamasındaki `content` değeri; tanımlıysa kök `layout.tsx` meta etiketini basar.
- `ADMIN_USERNAME`, `ADMIN_PASSWORD_HASH`, `ADMIN_SESSION_SECRET` – `/admin` paneli girişi. Özet `scrypt.<salt>.<hash>` biçimindedir (`$` kullanılmaz, dotenv genişletir); ikisini `npm run admin:hash` üretir. Biri eksikse giriş "yapılandırılmadı" der. Örnek: `.env.example`; gerçek değerler `.env.local` (git'e girmez) veya barındırma panelinde.

## İçerik nerede düzenlenir

- **İletişim bilgileri** (telefon, WhatsApp, e-posta, adres, harita, çalışma saatleri): panelden `/admin/iletisim` → `content/site.json` (`src/lib/admin/contentValidation.ts` → `validateContact`). `src/data/site.ts` bu dosyayı derlemede içe aktarır (istemci bileşenleri senkron kullanır); bu yüzden değişiklik geliştirmede hemen, production'da bir sonraki build'de yansır. WhatsApp dışındakiler şu an `null`; arayüz bu durumda "Bilgi yakında eklenecek" gösterir, JSON-LD'ye de eklenmez. Gerçek bilgi verilmeden uydurma değer girilmez.
- **WhatsApp mesajları**: `src/lib/contact.ts` → `buildWhatsAppMessage` (hizmet / marka / araç grubu / randevu bağlamına göre).
- **Hizmetler**: `src/data/services.ts`
- **Araç grupları**: `src/data/vehicleTypes.ts`
- **Markalar**: `src/data/brands.ts`. Ana sayfa marka kutularındaki tek renkli logolar `src/assets/brands/*.svg`, kaydı `src/data/brandLogos.ts` (anahtar `brands[].plain`, kaynak + lisans). Yalnızca açık lisanslı logo kullanılır: Simple Icons (CC0) veya Wikimedia Commons'ta "Public domain" işaretli SVG; yeni markada logo yoksa kutu yalnızca adı gösterir. Logolar `brands.ts`'e import edilmez (istemci bileşenleri de kullanır). `segment` alanı yedek parça filtresinde markayı araç grubuna bağlar.
- **Yedek parça kataloğu** (`/yedek-parca`, ürün detayları, ana sayfa özeti, footer, sitemap): `content/catalog.json` → `categories` (alt kategorileriyle) ve `parts`. Normalde **admin panelinden** düzenlenir; elle düzenlerken şemaya (`src/lib/catalog/types.ts`) uy. Okuma yalnızca sunucuda `getCatalog()` ile yapılır (`src/lib/catalog/store.ts`), istemci bileşenlerine `catalog` prop'u geçer (tüm katalog yalnızca filtre/arama için `PartsCatalog`'a; sepet `PartsCart` sadece `toCartParts(catalog)` alır, aksi halde her sayfanın HTML'i yüzlerce KB büyür); saf yardımcılar (`findPart`, `partFitsBrand`, `suggestPartCode`, `slugify`…) `src/lib/catalog/helpers.ts`. Her ürünün `code` alanı (`SO-<KATEGORİ KODU>-<NO>`) WhatsApp siparişinde ürünü tanımlar; firmanın gerçek stok kodları gelince değiştirilir. `oemCodes` üretici / OEM parça numaralarıdır (panelde "OEM / orijinal parça numaraları"); ürün sayfasında, meta açıklamada, Product şemasında (`mpn`, `additionalProperty`) ve katalog aramasında (tire/nokta olmadan da) kullanılır; yalnızca doğrulanmış numaralar girilir. `updatedAt` panel kaydında otomatik yazılır ve sitemap `lastModified` olur. `fitment` yalnızca firmanın belirttiği model/motor uyumu içindir; uydurma model veya yıl girilmez. `brands` dolu ürünler markaya özeldir; boşsa ürün o araç grubundaki markalara uygun sayılır (`partFitsBrand`). Marka listesi ve kodları `src/data/brands.ts`. Kartlardaki "Uygun Araçlar" çipleri (`FitmentChips` → `fitmentItems`) önce `fitment`, yoksa uyan araç markalarını yazar (ilk 4 + "+N"); `engineMaker` işaretli motor üreticileri (Deutz, Cummins) bu listeye girmez, `fitment`'e de motor üreticisi yazılmaz (aramada bulunması için `keywords` kullanılır). "Tüm Ürünler" menüsü `src/components/PartsMenu.tsx` (mobilde soldan panel, masaüstünde açılır menü; veri `toPartsMenu(catalog)`); `/yedek-parca`, kategori, marka ve ürün sayfalarının breadcrumb satırındadır. Menüyü saran öğeye `z-index` verilmez, yoksa mobil panel header'ın altında kalır. Katalog filtresi (`PartsCatalog`) kategori / alt kategori / marka / araç grubu / ürün markası / parça türü sayılarını `countWith` ile hesaplar; arama, filtre, sıralama ve URL mantığı `src/lib/catalog/filters.ts`'tedir. Filtre durumu URL'de tutulur (`q`, `category`, `sub`, `segment`, `brand`, `model`, `engine`, `year`, `quality`, `maker`, `sort`, `page`; geri/ileri çalışır) ve `useUrlSearch` / `writeUrlSearch` (`src/lib/catalog/useUrlSearch.ts`) ile okunur/yazılır; `useSearchParams` kullanılmaz (SSR'da ürün listesi boş kalır). Sıralama: Önerilen, A–Z, Z–A, En yeni (`updatedAt`), Ürün kodu; fiyat olmadığı için fiyat sıralaması ve stok filtresi eklenmez. Katalog kartı `PartCard` (görsel → kategori → ad → ürün / OEM kodu → uygun araçlar → teklif listesi). Ürün kartı butonu "Sepete Ekle" / "Sepette · N"; panel, ürün sayfası ve WhatsApp metinlerinde "Teklif Listesi" denir (ödeme yok). Araç seçici Marka → Model → Motor → Yıl; model/motor/yıl önerileri yalnızca ürünlerin `compatibility` satırlarından gelir (`vehicleOptions`), model filtresi yalnızca o marka için model satırı olan ürünleri daraltır (`partFitsModel`). `compatibility` (panelde "Uyumluluk tablosu", satır başına `Marka | Model | Motor | Yıl`) ürün sayfasında tablo olarak gösterilir; `gallery` (panelde "Ek görseller", `images.ts` anahtarları) birden fazla görsel varsa küçük resimli galeri açar. İkisi de isteğe bağlıdır ve yalnızca doğrulanmış bilgiyle doldurulur. Kategori ikonları `src/components/partCategoryIcons.ts` (`categories[].icon`). Sepet ve seçili araç `src/lib/partsCart.ts` (localStorage), sipariş mesajı `buildWhatsAppMessage` → `order`, toplu parça listesi (`PartList`) → `partList`. Sayfa metni ve güven şeridi `src/data/parts.ts` → `partsIntro` / `partsPerks`; yalnızca firmanın gerçekten sunduğu hizmetler yazılır. `qualities` (orijinal / muadil) yalnızca firmanın belirttiği parçalara girilir; stok adedi veya fiyat eklenmez. `manufacturer` ürünün üretici markasıdır (Bosch, Valeo…; araç markası değil), `specs` "Özellik: Değer" satırlarından oluşan ürün özellikleri tablosu, `details` ürün sayfasındaki detaylı açıklamadır (paragraflar boş satırla); üçü de panelden girilir, isteğe bağlıdır ve yalnızca firmanın verdiği bilgiyle doldurulur. `manufacturer` Product şemasında `brand`, `specs` `additionalProperty` olur; panel aynı markanın farklı yazımlarını mevcut yazıma birleştirir. Kart görseli kategorinin `imageKey`'inden gelir; ürüne özel görsel için `parts[].imageKey` (`src/data/images.ts` anahtarı) verilir.
- **Admin paneli** (`/admin`, giriş `/admin/giris`, `noindex` + robots disallow): ürün ekle / düzenle / sil, kategori ekle / düzenle / sırala / sil (ürünü olan kategori silinmez), alt kategori ekle / yeniden adlandır / sırala / sil (silinen alt kategorinin ürünleri kategoride kalır). Oturum: `src/lib/admin/auth.ts` (scrypt şifre özeti, HMAC imzalı httpOnly çerez, 8 saat, IP başına 15 dakikada 5 hatalı deneme). Doğrulama `src/lib/admin/validation.ts` (katalog) ve `contentValidation.ts` (galeri / iletişim), server action'lar `src/app/admin/actions.ts` (katalog) ve `contentActions.ts` (galeri / iletişim); her kayıttan sonra `refreshSite()` (`src/lib/admin/routing.ts`). Arayüz: masaüstünde sol yan menü, mobilde soldan açılan menü (`AdminNav`); panel ana sayfası sayılar, kategoriler, "Site durumu" eksik bilgi listesi ve son güncellenen ürünleri gösterir. Ürün listesi (`PartsTable`) çoklu seçimle toplu silme / kategoriye taşıma (`bulkPartsAction`, taşınan ürünün alt kategorisi boşalır) yapar; "Kopyala" (`/admin/urunler/yeni?kopya=<slug>`) ürünü yeni slug ve kodla şablon olarak açar. Panel sayfaları `src/app/admin/(panel)/`, bileşenleri `src/components/admin/`. Yeni panel sayfası `(panel)` grubuna eklenir ve `requireAdmin()` çağırır; her server action da `requireAdmin()` ile başlar.
- **Depolama (veritabanı yok)**: `catalogStore` şu an JSON dosyasına yazar. Vercel/Netlify gibi sunucusuz ortamlarda dosya yazımı kalıcı değildir; veritabanı bağlanana kadar panel yerelde (`npm run dev`) kullanılıp `content/catalog.json` commit edilir ya da site kalıcı diski olan bir sunucuda çalıştırılır. Veritabanına geçişte yalnızca `src/lib/catalog/store.ts` içindeki `CatalogStore` (`read` / `write`) uygulaması değiştirilir.
- **Hakkımızda, avantajlar, süreç, CTA metinleri, yetkinlik göstergeleri**: `src/data/company.ts`. Gerçek istatistik geldiğinde `capabilities[].value` / `valueCaption` doldurulabilir; sahte rakam eklenmez.
- **Menü, section id'leri, üst duyuru şeridi (`topBar`), hızlı bağlantılar (404 / teşekkür / yasal sayfalar)**: `src/data/navigation.ts`
- **SSS** (ana sayfa + FAQPage şeması): `src/data/faq.ts`
- **Müşteri yorumları**: sitede ve panelde yorum bölümü yoktur (kaldırıldı); AggregateRating / Review şeması basılmaz.
- **Atölye galerisi** ("Atölyeden Gerçek Kareler"): panelden `/admin/galeri` ile yüklenir, açıklama düzenlenir, sıralanır, silinir. Kayıt `content/gallery.json`, dosyalar `content/uploads/galeri/*.webp` (`public/` değil; build sonrası eklenen dosyalar orada sunulmaz) ve `/galeri/foto/[file]` route'undan sunulur. Yükleme `src/lib/content/galleryUpload.ts`: `sharp` ile döndürme düzeltme, en fazla 2400 px, WebP, EXIF silinir, bulanık önizleme üretilir; dosya başına 15 MB, en fazla 60 fotoğraf (`src/lib/content/gallery.ts`), istemci her fotoğrafı ayrı action ile gönderir (`next.config.ts` → `serverActions.bodySizeLimit: "16mb"`). Ana sayfada ilk 6 fotoğraf (`WorkshopGallery`) + "Tüm Galeri" bağlantısı; `/galeri` sayfası (`GalleryGrid`, masonry + tam ekran görüntüleyici: ok tuşları, kaydırma, Esc) fotoğraf yokken 404 döner ve sitemap'e yalnızca fotoğraf varken girer. Yalnızca işletmenin kendi fotoğrafları yüklenir. Depolama `src/lib/content/store.ts` (`mutateContent` yazmaları sıraya koyar); sunucusuz ortamda kalıcı değildir (katalog depolama notuna bakın).
- **Geliştirme önizlemesi**: galeri boşken yalnızca `npm run dev` sırasında (`isDevPreview`, `src/components/DevPreviewNote.tsx`) metinsiz iskelet + "Geliştirme önizlemesi" notu gösterir; production build'e girmez. Ana sayfa bölüm numaraları (08+) galerinin görünürlüğüne göre `src/app/page.tsx` → `trailingIndices` ile hesaplanır.
- **Hero metni**: `src/data/company.ts` → `heroContent` (başlık satırları + açıklama). Açıklamada yalnızca `src/data/brands.ts`'teki markalar geçer. Araç grubu ikonları `capabilities[].icon` → `src/components/capabilityIcons.ts` (`CarIcon`, `VanIcon`, `BusIcon`, `EngineIcon`); hero şeridinde ve Hakkımızda kartlarında kullanılır.
- **Yedek parça özeti metrikleri** (`PartsTeaser`): yalnızca veriden türeyen sayılar (`brands.length`, `services.length`, katalog kategori sayısı) + `partsIntro.stock`; sayaç `CountUp` (sunucuda son değeri basar, hareket azaltmada sabit kalır). Uydurma istatistik eklenmez.
- **Servis talep formu** (`AppointmentForm`): Ad Soyad, Telefon, Araç zorunlu (satır içi hata, `aria-invalid`), Hizmet ve Mesaj isteğe bağlı; WhatsApp mesajına dönüşür (`buildWhatsAppMessage` → `appointment`, `phone` dahil) ve `/tesekkurler`'e geçer. "Yol Tarifi Al" butonu yalnızca `site.contact.mapUrl` doluysa görünür.
- **SEO**: `src/data/seo.ts` → `pageSeo`. Her sayfanın benzersiz başlık, meta açıklama ve sosyal medya metni buradadır; metadata `src/lib/metadata.ts` → `buildPageMetadata` ile üretilir. Kendi `opengraph-image` dosyası olan segmentlerde `{ ownOgImage: true }` verilir (aksi halde metadata görseli dosyayı ezer).
- **Gizlilik politikası**: `src/app/gizlilik/page.tsx` (indekslenir). KVKK metni `src/app/kvkk/page.tsx` hâlâ yer tutucu ve `noindex`.

## Sayfalar ve ortak bileşenler

- **Katalog SEO adresleri** (programatik SEO, `src/lib/seo/`): `/yedek-parca/[slug]` sırasıyla marka → kategori → ürün olarak çözülür (`resolveCatalogSlug`); `/yedek-parca/[slug]/[sub]` marka + kategori (örn. `/yedek-parca/renault/fren-sistemi`) veya marka + model, `/yedek-parca/[slug]/[sub]/[leaf]` marka + model + kategori. Model sayfaları yalnızca ürünlerin `compatibility` satırlarından doğar (uydurma model sayfası yok). Veri ve indeksleme kuralları `src/lib/seo/catalog.ts`: marka sayfası en az 1 markaya özel ürün (`brands` veya uyumluluk satırı) varsa, kategori en az 1 ürün varsa indekslenir; marka + kategori hiç ürün yoksa 404, yalnızca genel parça varsa `noindex, follow` (sitemap'e girmez, kısayollarda linklenmez). Başlık / açıklama / H1 / giriş metni / SSS `src/lib/seo/copy.ts` (gerçek sayı, kod ve kategoriden üretilir; markalar arası kopya metin yazılmaz; ağır vasıta ve motor markaları `brandHeading` ile ayrı niyet alır: "Deutz Motor Yedek Parça", "Otokar Otobüs Yedek Parça"). Sayfa düzeni `src/components/CatalogLandings.tsx` → `PartListing` (breadcrumb, giriş, kısayollar, ürün grupları, servis, görünür SSS + FAQPage, ilgili bağlantılar). Ürün detayı `src/components/PartDetail.tsx`. Eski `/yedek-parca/marka/*` ve `/yedek-parca/kategori/*` adresleri `next.config.ts`'te tek adımlı 301 ile yönlenir. Panelde SEO alanı gösterilmez; ürün SEO başlığı / açıklaması her zaman otomatik üretilir (`src/lib/seo/partSeo.ts`: başlık = ad + kod, açıklama = kod + ad, uygun araçlar, özellikler, OEM, kısa açıklama; ≤160), kategoriler de `copy.ts`'ten. `seoTitle` / `seoDescription` yalnızca `content/catalog.json`'a elle yazılırsa otomatiği ezer; panelden kaydedilen ürün / kategoride bu alanlar yazılmaz, metin otomatiğe döner. Panel düzenleme / ekleme sayfalarında `BackLink` ("Ürünlere / Kategorilere Dön") vardır. Sitemap: `/sitemap.xml` (sayfalar + indekslenen açılış sayfaları) ve `/yedek-parca/sitemap/<n>.xml` (ürünler, 10.000'lik parçalar; `src/lib/seo/sitemaps.ts`); `lastModified` yalnızca gerçek `updatedAt`'ten. robots.txt filtre/arama adreslerini (`/yedek-parca?`) taratmaz; filtreli katalog canonical'ı `/yedek-parca`.
- `/yedek-parca/[slug]` (ürün): her ürünün detay sayfası ve paylaşım görseli `content/catalog.json` içindeki `parts` listesinden build'de statik üretilir; panelden sonradan eklenen ürünler ilk istekte render edilir (`dynamicParams` açık). Slug kayıttan sonra değiştirilemez; marka adları, kategori kimlikleri, `kategori`, `marka`, `urun-markasi` ve `sitemap` slug olarak kullanılamaz (`reservedPartSlugs`, `isReservedPartSlug`); yeni kategori adı da marka / ürün adresiyle çakışamaz. Ürün sayfasında "Uygun Araçlar" yalnızca araç uyumunu, "Ürün Özellikleri" tablosu kod / ürün markası / OEM / kategori / parça türü + `specs` satırlarını, "Ürün Açıklaması" `details` paragraflarını (yalnızca doluysa) gösterir. "Parça + Usta" bağlantısı kategorinin `serviceSlug` alanından gelir; başlığı `src/data/parts.ts` → `installHeadlines` (önce kategori `id`, sonra `serviceSlug`), butonları "Servisi İncele" (`/#<slug>`) ve "Randevu Al" (`homeContactHref`). Ürün kodu ve OEM kodları kopyalama butonludur (`CopyButton`). WhatsApp ürün sorusu (`part` + `url`) ve şasi numarasıyla uyumluluk sorusu (`compatibility`) mesajları ürün URL'sini `site.url` ile içerir; şasi numarası yalnızca kullanıcının WhatsApp'ta yazacağı boş satırdır, sitede tutulmaz. Benzer ürünler `relatedParts` (kategori, alt kategori, marka, ürün markası ve özellik benzerliğiyle puanlanır, 4 adet). Katalog hata ekranı `src/app/yedek-parca/error.tsx`.
- Kategori (`/yedek-parca/<kategori>`) ve marka (`/yedek-parca/<marka>`) açılış sayfaları tüm ürünleri sunucuda, kod + adla taranabilir bağlantı olarak listeler (`PartListing`, kart `PartLinkCard`) ve `ItemList` şeması basar. Marka slug'ı `brandSlug` (`brands[].plain`'den), yollar `partCategoryHref` / `partBrandHref` / `partBrandCategoryHref` / `partModelHref`. Footer, ürün sayfası ("Tüm ürünler" satırı marka + kategori sayfasına gider), "Tüm Ürünler" menüsü ve `/yedek-parca` altındaki "Kategoriye / Markaya Göre" bölümü bu sayfalara gider.
- `/yedek-parca/urun-markasi/[slug]`: ürün (üretici) markası sayfası; yalnızca en az bir üründe `manufacturer` girilmiş markalar için var (`catalogManufacturers`, yol `partManufacturerHref`), yoksa 404. "Tüm Ürünler" menüsündeki "Ürün Markaları", katalog filtresindeki "Ürün Markası" ve `/yedek-parca` altındaki "Ürün Markasına Göre" bölümü bu listeden beslenir.
- `/tesekkurler`: randevu formu WhatsApp'ı açtıktan sonra yönlendirilen sayfa (`noindex`, robots.txt'de disallow).
- `not-found.tsx`: özel 404 sayfası.
- `SiteShell`: ana sayfa dışındaki sayfaların header/footer/sticky iletişim iskeleti. İletişim bölümü olmayan sayfalarda `contactAnchor={homeContactHref}` kullanılır.
- `Breadcrumb`: görsel sayfa yolu + BreadcrumbList şeması.
- `StickyContact`: masaüstünde yüzen telefon/WhatsApp, mobilde kenarlardan boşluklu ince çubuk (telefon yalnızca numara tanımlıysa ikon olarak, WhatsApp yalnızca numara varsa, Randevu her zaman).
- `Brands`: binek & hafif ticari (5 sütun + "ve her türlü araç" kutusu) ve ağır vasıta (4 sütun) grupları, mobilde 2 sütun. Kutuda logo (CSS `mask` ile tek renk: normalde gri, hover'da kırmızı; `aria-hidden`) + metin olarak marka adı. Alttaki not logoların tescilli marka olduğunu ve yetkili servis olmadığımızı belirtir; kaldırılmaz.
- SSS akordeonu `details`/`summary`; yumuşak açılma `globals.css` → `.faq::details-content` (destekleyen tarayıcılarda, hareket azaltmada kapalı).

Dekoratif doku (noise, grid, köşe işaretleri) kullanılmaz.
- Tüm fotoğraflar `src/assets/images/` altında yereldir ve `src/data/images.ts` kaydından kullanılır (kaynak URL + lisans bilgisiyle).
- Yedek parça görselleri `src/assets/images/parts/` (`images.ts` → `part*` anahtarları): parça türüne göre seçilmiş Unsplash / Pexels fotoğraflarıdır, markaya özel ürün fotoğrafı değildir. Aynı türdeki ürünler (örn. tüm "Fren Balata Seti"leri) aynı görseli paylaşır. Araç / parça markalarının resmi ürün fotoğrafları telifli olduğundan izinsiz eklenmez. Uygun açık lisanslı fotoğraf bulunamayan ürünler (fren hidroliği, çift kütleli volan, kızdırma bujisi) yanlış parça göstermemek için genel atölye görselindedir; firmanın kendi ürün fotoğrafları geldiğinde bunlar öncelikle değiştirilir.
- Yalnızca Unsplash License (Unsplash+ değil), Pexels License veya işletmenin kendi fotoğrafları ("Firma fotoğrafı") kullanılır. Yeni görsel eklerken `source` ve `license` alanlarını doldur.
- Gerçek işletme fotoğrafları geldiğinde aynı dosya adıyla değiştirmek veya `images.ts` içindeki import'u güncellemek yeterlidir.

## Kurallar

- Sahte yorum, puan, istatistik, adres, şehir veya telefon eklenmez.
- Sayfada tek `h1` vardır (Hero). Yeni bölümler `h2` ile başlar, kart/öğe başlıkları `h3`; seviye atlanmaz. Footer sütun başlıkları ve sepet paneli başlık etiketi kullanmaz (`p`).
- Satırlara bölünmüş başlıklarda (`block` span) satır sonuna `{" "}` konur; aksi halde arama motoru kelimeleri bitişik okur. Süs numaraları (01, 02…) başlığın dışında ve `aria-hidden` olur.
- Meta başlık ≤ 60, açıklama ≤ 160 karakter; dinamik açıklamalar `fitDescription` ile kısaltılır. Ürün sayfaları `buildProductSchema` (fiyat bilinmediği için `offers` yok), ana sayfa `buildWebSiteSchema` basar.
- Animasyonlar `prefers-reduced-motion` kurallarına uyar; reveal animasyonu `RevealObserver` + `data-reveal` ile çalışır. Gözlenen elemana doğrudan `clip-path` verme (IntersectionObserver tetiklenmez); maske için iç `data-mask` sarmalayıcısını kullan.
- Discriminated union üzerinde `switch` kullanırken `default` dalında `never` kontrolü yapılır.
- İçe aktarmalar dosyanın başında olur.
- Aikido (veya başka ücretli) güvenlik taraması çalıştırılmaz; kullanıcı istemiyor. Doğrulama döngüsü yukarıdaki typecheck + lint + build'dir.

## Deploy

Vercel veya Netlify'da ek ayar gerekmeden çalışır (`npm run build`). Yayına almadan önce `NEXT_PUBLIC_SITE_URL` tanımlanmalı ve `src/data/site.ts` içindeki iletişim bilgileri doldurulmalı. Panel kullanılacaksa `ADMIN_*` değişkenleri barındırma panelinde tanımlanır (yukarıdaki depolama notuna bakın). Yayından sonra site Google Search Console'a eklenir (`GOOGLE_SITE_VERIFICATION`) ve `https://<alan-adı>/sitemap.xml` ile `https://<alan-adı>/yedek-parca/sitemap/0.xml` gönderilir (robots.txt ikisini de listeler). KVKK / Gizlilik sayfaları (`/kvkk`, `/gizlilik`) şimdilik yer tutucudur ve `noindex` durumundadır.
